# R7 deployed — penjaga R:R keras + validasi urutan level (24 Okt 2026)

## Masalah
`rrr_min` hanya dipakai untuk MENGHITUNG `reward = risk * rrr_min`. Tidak pernah
dipakai untuk MENOLAK. Bila pembulatan atau clamp `max_sl_points` menghasilkan
rasio di bawah minimum, sinyal tetap dikirim ke EA. Urutan level juga tidak
diperiksa, sehingga kesalahan tanda bisa lolos sampai eksekusi.

## Perubahan (`multi_session_laya.py`)

1. Setelah `risk`/`reward` dihitung:
   - `risk <= 0` atau `reward <= 0` -> sinyal dibatalkan
   - `reward/risk < rrr_min` (di luar toleransi pembulatan) -> sinyal dibatalkan
   Alasan disimpan di `last_block_reason` dan muncul sebagai `blocked_reason` di API.
2. Invarian arah level sebelum sinyal dikembalikan:
   - LONG : `sl < entry < tp1 < tp2`
   - SHORT: `sl > entry > tp1 > tp2`
   Bila tidak terpenuhi -> sinyal dibatalkan.

## Bug yang ditemukan saat mengerjakan R7 (dan diperbaiki)

Penjaga awal memakai toleransi `1e-9`, sehingga MENOLAK sinyal sah karena
pembulatan 2 desimal:

```
risk=2.53 -> reward=round(2.53*1.8, 2)=4.55 -> rasio 1.7984 < 1.8 -> DITOLAK
risk=2.99 -> reward=5.38 -> rasio 1.7993 -> DITOLAK
```

Terukur pada 6 nilai risk: **2 dari 6** ikut tertolak padahal sah (~33%).

Perbaikan: `toleransi = 0.01 / max(risk, 1.0)` — mencerminkan galat pembulatan
setengah sen pada reward. Rasio yang benar-benar jauh di bawah minimum tetap ditolak.
